# 产品愿景

> 这一页不讲技术。它是后续所有开发的"北极星"。

## 一句话

**一个统一管理、自由选择计算位置的 Minecraft 世界** —— 可以固定由自有服务器开服，也可以让服务器与玩家电脑共同调度。玩家打开游戏，连接同一个入口。

游戏可以固定跑在自有服务器，也可以由服务器和玩家电脑按策略轮流计算；被选节点退出时，系统安排交接。

## 朋友间互信与朴素交接（2026-10-10，已确认）

产品面向朋友间的合作开服。授权计算节点按互信方式参与，不做反作弊，不检测或裁决玩家修改 config、使用游戏 OP/命令等是否作弊，不为任意 MOD 建立恶意执行者验证机制。

云端负责实例发布、管理权限、选主机、稳定入口和最新已提交状态；实际运行节点执行正常 Minecraft 服务端。运行时文件在该节点正常读写，无需逐次访问云端。文档中的“逻辑主机”按此管理职责解释，不宣称云端已经执行/验证每次游戏行为。

正常交接采用：旧节点停止接收新写入并正常停服、完成持久保存；将完整房间状态上传成功；中心确认提交后释放旧任务；新节点按相同发布环境恢复并启动。需要覆盖世界、有效配置和世界外的模组持久数据。新建数据库/配置变化属于正常运行，不是作弊或安装损坏证据。

同步以发布组件和配置清单为依据，下载哈希用于完整性和普通故障修复。云端明确发布的开服配置按修订下发，本地主机改动不自动覆盖中心；个人配置、资源和房间运行数据分别保留，不进行全目录一致性封锁。额外 MOD 可作为整合包兼容选项，不作为反作弊封禁依据。

云端更新配置后，在线候选可预下载；领取任务启动前确认所需配置修订。当前运行不被在线覆盖，变更在下一次开服或正常重启生效。先恢复房间状态，再应用中心指定配置，防止旧节点存档覆盖新配置。具体边界见 [同步范围与云端配置版本](同步范围与云端配置版本.md)。

继续保留账号认证、云端操作权限、凭据隔离、路径边界、备份/恢复、唯一写入任务及过期提交拒绝。这些服务于正常管理和数据完整性，不能因为不做反作弊就允许两个节点同时覆盖同一份存档。朋友可在游戏内使用管理命令；哪些变更作为房间最新状态保存，与后续中心显式管理操作如何协调，需要由保存流程明确，不能把正常变更自动归为作弊。

主动交接等待最终提交；旧节点突然失联只能恢复最后成功提交的状态，不能宣称尚未上传的数据可恢复。不断线网关可继续作为后续体验优化，第一版交接正确性不以保留在线连接为前提。

当前已有原版停服/最终提交/恢复闭环；完整 MOD 外部数据迁移与上述宽松客户端同步策略仍待实现。当前 KAMUCL 云端同步适配尚未完成，不应把本节当作已经上线的行为。

## 玩家视角：一个真实的晚上

1. **晚上八点，你先上线。** 打开电脑上一个绿色小图标，点"我要玩"。
   几秒钟后，游戏里那个服务器地址变成"在线"了。
2. **你直接进游戏。** 地址永远是同一个，你甚至不用知道今天是谁在当主机。
3. **阿伟也上线了。** 他也点一下，直接进。你们俩一起玩——这局游戏其实跑在你电脑上。
4. **十点半你要睡了。** 你点"我下了"。这时候游戏没有关。系统按授权、意愿、资源和网络状况选择接管节点，可以是其他朋友，也可以是服务器。目标是切换期间由中心保留连接，玩家短暂等待后继续，不回服务器列表；该迁移体验尚待实现与实测。
5. **第二天你想自己玩。** 你一个人上线，游戏就在你自己电脑上跑，又快又爽。
6. **大家都下了。** 按房间的闲置策略让世界休眠，或者在指定服务器继续运行；存档由中心保存。

**核心体验：世界是连续的，地址是固定的，人是在变的。**

## 玩家要装什么、看到什么

**普通玩家**

- 装一次那个小托盘程序（目标是以后能免装）。
- 看到一个永远不变的服务器地址。
- 游戏里能看见"现在是阿伟在当主机""延迟多少"。

**房主**

- 一个面板：谁在线、现在谁当主机、世界最近一次备份是什么时候。
- 一键操作：指定某个人当主机、立刻备份、回滚到某个时间点。
- 设置规则：比如"只允许阿伟和大壮当主机"。

## 产品里其实只有三样东西

1. **一个入口** —— 永远不变的那个地址，玩家的门。
2. **一个调度大脑** —— 决定谁当主机、什么时候搬家、世界存哪。
3. **每个人电脑上的小助手** —— 负责开服、关服、搬世界。

原来那台低配小主机可以只当“大脑 + 门卫”；资源足够时，也可以运行 Minecraft，作为固定计算节点、按优先级参与调度，或作为兜底节点。网络入口支持公网 IPv4/IPv6、端口映射和外部穿透等适配，不强制所有用户使用同一款接入软件。

## 跟现有做法的区别

| | 现在的做法 | 我们的产品 |
| --- | --- | --- |
| 谁出机器 | 某个人一直开着，或租服务器 | **自有服务器固定运行，或服务器与玩家共同调度** |
| 朋友怎么进 | 装 Hamachi/Radmin，或要 IP | **一个固定地址，最好免装** |
| 主机下线 | 游戏结束，大家散伙 | **游戏搬个家，接着玩** |
| 没人玩时 | 服务器空转烧电 | **自动睡着** |
| 存档 | 在某个人电脑上，容易丢 | **持续备份，可回滚** |
| 大型整合包 | 得租台好服务器 | **吃玩家自己的电脑性能** |

## 一句话

> **一个"跑在朋友之间"的 Minecraft 世界。地址不变、存档不断、机器轮着用、没人时自己睡觉。**

## 新增部署要求（2026-10-10）

计算位置与网络接入独立配置。固定服务器模式兼容传统开服；混合模式保留中心管理权和稳定网关入口。全部世界计算在服务器上时，不要求玩家贡献算力。接入方式明确区分原生客户端可连接的 TCP 入口、私有组网以及需要辅助程序的方案。细节见 [计算节点与网络接入扩展](计算节点与网络接入-扩展需求.md)。
