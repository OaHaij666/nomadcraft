# 严格一致范围：第一手资料调查与同步清单建议

调查日期：2026-10-10。范围：Java Edition、Fabric、Forge 1.20.1、NeoForge 1.21.1/现行配置文档、Modrinth mrpack、packwiz、KubeJS、CraftTweaker、Paper。状态：调查与设计建议，未改动同步运行代码。

## 产品范围修订（2026-10-10）

用户已明确限定朋友间互信、不做反作弊。下文保留官方事实和早期严格策略研究，不代表所有候选策略都要实施。第一版不维护每个 MOD 的关键配置知识库，不拦截 config/OP 的正常变更，新增客户端扩展按兼容性处理。只维护发布组件清单、故障完整性检查和完整房间数据交接，详见 [产品愿景](产品愿景.md)。

## 结论

严格一致的对象是发布版声明的组件、加载入口、玩法定义和关键配置值。客户端与计算节点各自对自己的发布清单一致，二者的目录或字节集合不必相同。

清单按三种检查表达：不可变产物用哈希；自动序列化的混合配置检查规范化后的指定键；权限、规则等中心动态数据按授权版本下发。对不同平台、不同职责选择对应产物，不要求 Windows 客户端和 Linux 服务端复制同一份 libraries/natives 或整个 Java 安装。

这是一套产品选择，不是“Minecraft 要求所有联机玩家的文件哈希完全一样”的官方规定。

## 默认应纳入的对象

| 对象 | 客户端 | 计算节点 | 检查边界 |
| --- | --- | --- | --- |
| 固定 MC/加载器身份 | 是 | 是 | 固定 MC ID、加载器类型/版本；分别校验该侧核心与加载器产物。客户端 JAR 不等于服务端 JAR |
| 实际启动依赖 | 是 | 是 | 清单/安装配方解析出的 classpath、必需库和本平台依赖；只管理当前发布用到的文件 |
| 必需 MOD 与其必需依赖 | 按客户端清单 | 按服务端清单 | 固定 mod ID、产物哈希、依赖闭包；只在声明需要的侧安装 |
| 内容注册与初始化脚本 | 发布需要时 | 发布需要时 | 如 KubeJS startup_scripts 中注册物品/方块的脚本；按侧声明并固定源文件及必需支持文件 |
| 服务端玩法脚本/数据包 | 只在适配规则确有需要时 | 是 | KubeJS server_scripts、kubejs/data、房间批准的 datapack、对应版本的 CraftTweaker 脚本等 |
| 关键非网络同步配置 | 发布明确指定时 | 发布明确指定时 | 会改变注册、协议、物品/方块定义、玩法/生成等的配置；按具体 MOD/版本确定文件或键 |
| 依赖覆盖与加载控制 | 使用时 | 使用时 | 如 config/fabric_loader_dependencies.json；存在/缺失本身也是策略，不能允许未声明的覆盖文件静默改变加载规则 |
| 中心游戏规则、认证和权限 | 不下发服务端权威文件 | 是，中心动态策略 | 不当作发布时固定哈希；通过管理 API/命令和授权策略生成/更新 |
| 整合包必需客户端展示内容 | 声明必需时 | 通常不需要 | 必需资源、KubeJS client_scripts/assets 等按发布选择；仍允许独立个人资源层 |

额外可执行组件与“固定文件是否损坏”分开检查。mods 中未授权的新增 JAR、脚本加载目录中的未声明脚本不能仅因不在哈希清单就直接放行；普通数据库/缓存不能仅因出现在同目录就直接阻止启动。加载边界由加载器/模组版本适配决定，不是只检查后缀。

## 证据与容易误判的地方

### MC 核心、启动依赖和 Java

直接获取 Mojang 官方 1.20.1 元数据：client 与 server 的下载产物及 SHA-1 不同；javaVersion.majorVersion=17；libraries 有按 OS 选择的 rules。例如 java-objc-bridge 仅 macOS、epoll 依赖分别供 Linux 架构使用。

已保存来源 URL、metadata SHA-1、核心产物信息、平台依赖示例：proofs/strict-sync-mojang-metadata-2026-10-10.json。网页读取工具无法解析这些 JSON，改用本机 HTTPS 直接获取，未以第三方转载替代。

建议按发布配方检查关键启动定义和选中的库；KAMUCL/加载器生成或改写的本机路径、实例显示名等字段不应简单整文件字节比较。Java 检查支持版本范围/架构，并允许适配后通过的运行时；JDK 补丁版本、安装路径、内存、GC、窗口大小不纳入全体玩家统一哈希。若某个发布确需专用运行时，可在该发布单独声明。

### MOD 侧别和依赖

Fabric fabric.mod.json 的 environment 表示可加载物理侧，depends 等表示依赖；environment=* 只能说明允许在哪些侧运行，不等于必须安装在两侧，也不证明必须和服务器版本完全相同。[1]

NeoForge 的依赖元数据包含版本范围、required/optional 等类型和依赖 side；side 不能误当成整个 MOD 的可靠联机需求标签。[2]

mrpack 支持每个文件的 client/server required/optional/unsupported，并有 overrides、client-overrides、server-overrides。[3] packwiz 支持 side=both/client/server、可选组件及文件 preserve。[4,5]

建议优先采用整合包侧别/可选声明，加上 MOD 依赖分析和管理员覆盖；未知信息标待确认，不凭文件名断言客户端 MOD 或服务端 MOD。我们的“必需项固定精确产物”是便于复现和支持的产品策略；不是声称加载器普遍只允许相同哈希联机。

### 配置不能整目录锁死

Forge 1.20.1 官方表格：CLIENT 仅客户端且不网络同步；COMMON 两侧各自加载且不自动同步；SERVER 在服务端加载并同步到客户端，物理服务端位置为 world/serverconfig。[6]

NeoForge 1.21.1 和现行文档还说明 STARTUP 不自动网络同步，并警告用它改变注册内容可能导致两侧不同步；COMMON 也不自动同步，SERVER 则会同步。[7]

建议：CLIENT 默认本地；COMMON/STARTUP 先分析作用，只有影响共享环境的文件或键严格统一；SERVER 由计算节点使用中心/房间权威版本，普通远程客户端不用启动器复制 world/serverconfig。文件后缀只是默认约定，MOD 可以指定文件名，不能依赖 *-client.toml 猜测完成分类。[6,7]

自动重写注释、排序、默认值的配置，应有解析适配器比较关键键；没有适配器的混合配置不要假装支持键级锁定，应提示管理员选择整文件管理或本地保留。defaultconfigs 与房间已生效 serverconfig 分开管理，不能把模板更新当成覆盖已有存档配置的授权。

### 脚本、数据与资源应按功能拆分

KubeJS startup_scripts 用于物品/方块注册等启动阶段工作；server_scripts 用于配方、标签、掉落和服务端事件；client_scripts 用于 JEI/REI、提示等客户端事件。[8,9,10]

kubejs/data 类似数据包，kubejs/assets 类似资源包；kubejs/exported 是导出数据。不能严格比较整个 kubejs/。[11,12,13]

建议默认固定发布的 startup 源文件与必要注册配置；固定计算节点的 server_scripts/data；客户端 client_scripts/assets 是整合包“客户端必需展示”规则，可管理指定文件而不强制与服务端相同。导出物和日志排除。

CraftTweaker 不同版本的联网行为不同：1.12 官方文档要求脚本在两侧；1.18 文档说明服务端发送脚本，客户端可以无本地脚本加入。1.20 文档说明脚本位于 scripts 并使用 .zs。[14,15,16] 因此不能写一个跨版本通用的“客户端 scripts 全目录必须与服务器一致”规则。

Minecraft 官方资料将外部数据包放在 world/datapacks。[17] 建议在房间侧锁定管理员批准的数据包内容/启用集合；其内容随房间策略或存档迁移处理，不下载整个世界给普通客户端。不能全目录锁定 world/，因为世界本身会正常变化。

### 权限文件是动态权威状态

Paper 官方文档区分配置、插件 JAR、插件目录、日志和用户缓存，说明 ops/whitelist 等是可由命令更新的服务端数据文件。[18,19]

建议中心管理 server.properties 中关键规则、认证、OP、白名单和封禁的有效值与授权更新；不把首次发布时的文件哈希永久冻结，也不允许计算节点上传的数据库覆盖中心授权。实际端口、本机路径等由执行部署生成，可与别的节点不同。游戏内命令若允许修改这些状态，需要中心授权和回传协调。

## 默认不进入严格一致

作为我们的默认策略：个人 shaderpacks/resourcepacks、options.txt/画质/按键、截图、普通客户端标记/小地图数据、SQLite 等运行数据、缓存、日志、崩溃报告、导出物不进入固定环境哈希。必需资源是指定文件的例外，不意味着整个个人资源目录被锁死。

kubejs/config/defaultoptions.txt 官方设计就是首次设置用户选项，避免每次更新覆盖用户配置，支持“首次提供”模型。[20] packwiz preserve 也提供保留用户文件的成熟先例。[5]

## 发布清单生成流程

1. 从安装配方和包清单产生 client/compute 两个范围；记录依赖、来源和产物哈希。
2. 应用与 MC/加载器/MOD 版本绑定的适配规则，识别脚本入口、关键配置、运行数据和初始化模板。
3. 管理员审核未知文件及覆盖规则。导入包里包含某文件不自动意味着它必须长期严格一致。
4. 发布不可变清单；中心动态权限、房间配置、当前世界检查点分别引用自己的修订版本。
5. 启动前只检查本侧固定项、关键键和未授权可执行扩展；正常运行数据变化不触发重装。
6. 修复只替换受管理内容，保留本地资源与已登记运行数据，不在游戏运行时移动整目录。

推荐每个条目记录：path/componentId、role(client/compute)、mode(hash/keys/seed/local/runtime/center-policy)、reason、hash/关键键、条件(OS/架构/加载器)、来源、数据迁移策略。没有已知适配器时显示待审核，不以 blanket config/mods 递归哈希替代。

## 验收边界

原版、Fabric、Forge 1.20.1、NeoForge 1.21.1 分别验收：必需产物损坏/删除、未授权 MOD 或加载覆盖、COMMON/STARTUP 关键键变化、SERVER 网络同步、KubeJS 内容注册、服务端脚本/数据包、额外资源包、默认配置重写、SQLite 和世界更新、跨 OS 库选择、修复保留个人数据。

本次完成资料调查和清单设计。尚未执行这些改造验收或修改当前全目录指纹算法。依赖元数据与文件校验解决正常部署一致性，不能证明拥有系统控制权的人实际运行了什么。
