# 计算节点、网络接入与自检实现（2026-10-10）

本轮已经实现可配对的常驻服务器/玩家计算节点、房间放置策略、独立游戏入口配置和中心网络自检。没有启动外部穿透商、修改系统防火墙或替换用户数据。

## 计算节点

网页新增「计算节点」页面 /compute。普通用户可以配对自己的玩家节点；管理员可配对服务器节点并设置优先级。配对凭据仅在创建时返回并下载，中心只保存 token 哈希；节点列表不返回哈希或凭据。角色和身份来自登录会话，节点不能自行修改所有者或管理员优先级。

节点预算包括任务内存、给其它服务保留的可用内存和最大任务数量。CPU 与真实总/可用内存由 Rust sysinfo 从运行机器读取；这些是调度遥测，不能视为恶意执行者的可信证明。管理员可禁用节点或限制实例范围，禁用后不再分派，已有任务请求正常停止。

运行命令由界面生成：

~~~text
nomad-agent panel-node --credential-file "nomad-node-<id>.json" --data-dir "nomad-node-data" --java "java"
~~~

凭据文件包含配对的中心 API 地址、nodeId 和 token；应保密，不进版本库。远程中心要求 HTTPS，本机调试允许回环 HTTP。常驻执行器不需要桌面客户端或 Minecraft 游戏客户端；准备相应 Java 后即可独立运行。按 Ctrl+C，或启动时指定 --stop-file 并创建该文件，请求正常停服回传。

目前验证环境为 Windows + Java 21。Rust 程序具备跨平台代码路径，但 Linux 服务单元、服务器部署和真实跨电脑资源状态尚未实测。

## 房间策略

在实例详情的存档卡片点击「计算与网络」。

| 策略 | 实际行为 |
| --- | --- |
| 手动托管 | 保留KAMUCL 单次申请流程；常驻节点不会自动领取该房间 |
| 固定计算节点 | 只有指定节点满足条件后领取；离线/禁用不会偷偷选其他机器 |
| 自动调度 | 从授权、在线、资源合格且未退出自动候选的节点中评分选择 |
| 玩家优先，服务器兜底 | 有合格玩家时先选玩家，否则考虑指定或合格服务器 |

管理员优先级、玩家高/中/低意愿影响排序，但不覆盖授权、资源、并发和节点启用检查。none 排除玩家自动候选；服务器不继承管理员个人托管意愿。房间已有活动任期或待领取任务时，不会发第二份任务。现有运行任务保持当前节点，不会因新节点上线或分数变化立即迁移。

每个节点定时心跳/poll，中心在同一串行存储队列里选择并预留内存和任务容量，发出短期票据；任务实际运行仍走原版 panel-host 的独占 epoch、版本下载、世界恢复、就绪、检查点和最终提交。后台读取当前账号和权限，失效节点/账号不能继续申请。

修改房间计算或网络配置需要关闭房间并等待活动任务停止。已有房间默认仍是 manual，不会突然自动开服。此调度仅覆盖已配对、正在运行 panel-node 的节点；没有实现通过 KAMUCL 自动唤起其它电脑。

## 网络接入

每个存档可保存 kind、bindHost/bindPort、publicHost/publicPort、地址族及 frp 控制端信息。管理员可以选择公网/本机 TCP、通用外部 TCP 映射、frp TCP 穿透、私有组网或需客户端辅助的隧道。

原有临时房间端口模式作为未配置入口时的兼容默认；配置后在指定端口监听，并向玩家公布独立的公开端口。例如外部 30065 映射本地 25565，穿透控制端口 7000 不会被误公布为游戏入口。IPv6 字面地址格式化为 [address]:port。

这里的各种类型都是接入已有网络的配置，实际流量仍是原生 TCP。通用映射可以接入支持这种映射的外部工具；frp 页面可下载不含密钥的 frpc TOML 示例，localPort、remotePort、serverPort 分开生成。需要用户自行准备/运行相应程序，未自动安装第三方穿透、配置凭据或提供商业穿透账号。私网和客户端辅助类型在自检中显示客户端依赖。

配置的固定地址在正常停服后由下一任务重新监听；当前服务端结束时仍会关闭现有玩家连接。因此「公开地址保持不变」已验证，但「切换计算者不断线」仍待稳定协议网关与等待区实现。

## 网络自检

计算节点页提供管理员专用「中心网络自检」，无需房间运行：

- 本机接口和 IPv4/IPv6 地址情况；回环、私网、接口存在与公网可达不混淆。
- 中心 API 是否响应。
- 固定的 Mojang 版本元数据源 DNS 解析。
- 到已解析官方地址的出站 TCP 443，按 IPv4/IPv6 分别检测。

房间「计算与网络」中的自检额外包括保存的入口 DNS/地址族、实际房间监听、闲置执行器隧道和 Minecraft 原生状态协议响应。探测接受分片 TCP 数据，限制响应大小和超时，HTTP 200 不会被当作 Minecraft 成功。结果显示解析地址、地址族、延迟与协议版本。

检查只有中心侧视角；即使 Minecraft 返回正确状态，publicReachability 仍是 unverified。NAT 回流、入站防火墙、外部 IPv6 路由和第三方映射必须由异地客户端验证，不能显示「公网全部通过」。官方源 TCP 检查也不等于 HTTPS、认证服务和任意模组下载源都已验证；系统代理可能改变实际下载路径。

网络探测仅管理员可用，只测试已保存入口或固定官方源，不提供任意 URL/端口扫描参数。最多同时两组检查，DNS/TCP/协议等待都有时限。自检不会操作防火墙、端口映射或穿透服务。

## 实际验证

scripts/verify-compute-network.mjs 启动隔离真实面板，发布 Minecraft 1.20.1，配对 server 节点并设置 fixed。常驻 panel-node 自动领取任务并启动实际 Java 21 服务端。测试另开通用 TCP 映射入口，公开端口与房间监听端口不同，通过该入口完成原生状态查询和白名单玩家登录；自检识别协议 763，并保持外部网络未验证状态。

随后验证周期回传、最终停服、拒绝竞争节点，禁用旧 server 节点，切换 auto 并启动独立 player 节点。新节点自动部署、恢复世界中的验证标记，再次使用原公开地址连接，正常停服回传。报告在 docs/proofs/compute-network-2026-10-10.json。

两个节点和映射都在本机，不是两台物理电脑、实际公网或真实第三方 frps。游戏登录是专门隔离的 offline 白名单探针，不代表微软认证已经实测。正式服务端配置仍默认 onlineMode=true。

新模块验证包含固定约束、兜底、意愿、权限、内存与任务容量、重复请求、配置隔离、停用、原生协议分片与超时、frp 三种端口，以及前端不把中心侧自检渲染成公网证明。本轮验证：面板 100 项、前端 77 项、执行器 15 项单元及 3 项 HTTP 测试通过；公共模块 9 项、Daemon 144 项通过（1 项跳过）；完整公共 HTTP 联调 9 组通过，Windows 上未运行 Docker 组。面板、前端、执行器和 KAMUCL 构建通过。IPv4/IPv6 回环与单监听双栈使用真实 TCP 验证。

浏览器实际验证节点配对与凭据下载、中心自检、固定节点与不同公开/监听端口的保存；桌面和手机页面无横向溢出。报告见 docs/proofs/compute-network-ui-2026-10-10.json，截图在 docs/shots/compute-network-*-2026-10-10.png 与 room-compute-network-2026-10-10.png。

## 关键实现

- shared/nomad-compute.ts：节点、放置策略、入口与报告类型。
- panel/service/nomad_placement.ts：候选过滤与评分；nomad_catalog.ts：授权和串行任务预留。
- apps/agent/src/worker.rs：持续资源上报、自动领任务和停服。
- panel/service/nomad_ingress.ts、nomad_host_relay.ts：入口验证、frp 示例、实际监听与公开地址分离。
- panel/service/nomad_network.ts：DNS、网络接口、原生 Minecraft/TCP 检查。
- frontend/widgets/ComputeNodes.vue、catalog/RoomRuntime.vue：节点、房间策略与自检页面。

## API

POST/GET /api/nomad/hosting/nodes；PUT /nodes/:id；节点凭据 POST /nodes/:id/poll。房间配置 PUT /runtime/:instanceId/:saveId；管理员 POST /network/check 或 /network/:instanceId/:saveId/check；GET /network/:instanceId/:saveId/frp 导出示例。

中心元数据继续通过 Storage 持久化在 NomadCatalog，支持本地或 Redis。调度锁仍是单面板进程锁，多面板分布式协调没有实现。
