# NomadCraft 前端设计语言 v1

> 目标读者：以后改前端的自己。
> 这份文档是**约束**，不是灵感板。写代码前先读，做完对照检查。

---

## 0. 一句话定位

**这是一个"世界管理台"，不是"服务器管理后台"。**

玩家打开它，是为了**决定今晚和谁一起玩、玩哪个世界**。
管理员打开它，是为了**看这个世界现在在谁的电脑上跑、健不健康**。
其他一切都是配角。

## 1. 设计立场：游戏客户端，不是 IDE

MCSManager 原版是"一堆仪表盘的运维后台"——深色、密集、tab 套 tab、信息平铺。
我们要的是**游戏客户端**那种感觉：

| 维度 | 运维后台（不要） | 游戏客户端（要） |
| --- | --- | --- |
| 主角 | 表格和数字 | **世界本身**（一张会呼吸的卡） |
| 控件 | 表单、下拉框、checkbox 排成行 | 有物性的**按键、旋钮、铭牌** |
| 状态 | 状态点 + 文字 | **场景变化**：世界在谁家、亮不亮、多少人在 |
| 密度 | 越高越好 | 留白优先，一次只说一件事 |
| 导航 | 侧边树 | **世界 → 房间 → 实例** 三级纵深 |

**关键判据**：如果某个界面截图发到群里，朋友第一眼看到的是"哇这是个游戏吧"，
而不是"这是个后台吧"，那就对了。

## 2. 要留下的（MCSManager 的真血肉）

不重写、只重皮的能力：

- 实例生命周期（启停/重启/杀死/自动重启）
- 文件管理器、模组管理器、计划任务
- 终端/PTY 控制台
- 用户与权限、审计日志、操作日志
- 节点、性能图表、上传下载
- 快速开服模板、Java 版本管理

## 3. 要砍掉的

- steam / hytale / 基岩版 等非 MC-Java 主线（除非以后真要做）
- Docker 相关 UI（"docker 后面再说"）
- 与"世界"无关的仪表盘堆砌（原版的 PanelOverview 那种数字墙）

## 4. 色彩：暮色世界（Twilight World）

不要"纯黑 + 荧光绿"那种赛博味（skill 明确点名的 AI 味套路），也不要一片深蓝运维味。
**黄昏的天空**是我们的母题——一天里玩家最常上线的时刻，也是"世界"的隐喻。

| 名称 | 值 | 用途 |
| --- | --- | --- |
| `--nc-ink` | `#12131c` | 最底层的夜（不是纯黑，带一点紫） |
| `--nc-dusk` | `#1e1f30` | 面板底色，比 ink 亮一档 |
| `--nc-haze` | `#2b2c42` | 分隔/边框/次级面 |
| `--nc-parchment` | `#e8e4d9` | 主文字（暖白，比纯白柔和） |
| `--nc-mist` | `#9a97b0` | 次级文字（带紫的灰） |
| `--nc-aurora` | `#7ad4c8` | 唯一的行为色：在线、可用、主操作（青绿，像极光） |
| `--nc-ember` | `#e8894f` | 唯一的警示色：离线/危险（落日橙） |

**Why**：青绿 + 落日橙是黄昏天空里真实存在的一对颜色，撞在一起很贵气但不脏。
纯黑会显得廉价，带紫的墨色更"夜里"。

**纪律（skill 的"只花一次大胆"）**：
- 全局只有**两个**语义色（aurora/ember），其他地方一律用 ink/dusk/haze/parchment/mist 的中性层次。
- 不做渐变光晕、不做发光边框、不做彩色投影。**不许光污染。**
- 单屏内 aurora 的着色面积控制在 ~5%。

## 5. 字体

- **展示/标题**：`Space Grotesk`（有几何感、有性格，不是 Inter 那种默认脸）
- **正文/数字**：`IBM Plex Sans` + `IBM Plex Mono`（数字与代码用 mono，让状态数字有"仪表"感）
- 中文回退：`"PingFang SC", "Microsoft YaHei", sans-serif`

**判据**：字体本身就是性格。不许全用系统默认字体。

## 6. 布局：三级纵深

```text
┌──────────────────────────────────────────────┐
│  世界栏（World Rail）                          │
│  ┌────────┐  ┌────────┐  ┌────────┐          │
│  │今晚的世界│  │ 老存档 │  │ 建新的 │  ← 卡片  │
│  │ ● 在线  │  │ 休眠   │  │   +    │          │
│  │ 在 alex │  │        │  │        │          │
│  └────────┘  └────────┘  └────────┘          │
├──────────────────────────────────────────────┤
│  世界详情：HUD 条（谁在跑 / 几个玩家 / 延迟）    │
│  ┌────────────────────────────────────────┐  │
│  │  主机切换 · 存档版本 · 快照链 · 成员     │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

- **世界卡**是主角：大、有呼吸感、状态用场景表达（在线=有极光色描边+在谁家；休眠=暗淡）。
- **HUD 条**：一条横贯的状态带，承载"谁在跑 / 几个玩家 / 延迟 / 存档版本"。
- 详情页保留原版的能力，但用**面板**而不是表格来组织。

## 7. 控件：像精灵球，不像设置项

原版用的是 Ant Design 默认按钮。我们给按钮**物性**：

- 主操作（"唤醒世界"）：饱和 aurora 底 + 深色字，按压有 1px 下沉，hover 时轻微提亮（不做发光）。
- 次操作（"停止"）：只有描边，无底色。
- 危险操作（"杀死"）：haze 描边 + ember 字，**不填红**（填红是运维后台的做法）。
- 卡片 hover：**只抬 1-2px + 阴影加深**，不缩放、不发光。

## 8. 动效：只在"发生了一件事"的时候

- 世界上线/下线：一次 200ms 的极光描边扫过（一个 orchestrated moment）。
- 面板展开/收起：150ms 高度过渡。
- 不做的：每张卡入场 fade-up、每个按钮 hover 弹跳、数字滚动计数。**这些是 AI 味的重灾区。**

## 9. 落地顺序

1. 设计 token（CSS 变量 + Ant Design theme token）
2. 壳组件：AppSidebarMenu / AppHeader / AppBottomNav
3. 世界卡 + 世界列表
4. 世界详情（HUD 条 + 面板化）
5. 门禁/成员管理页（我们自己的特殊界面）
6. 逐个替换其余 widget

## 10. 自检清单（做完对照）

- [ ] 全屏只有一个强调色大面积出现
- [ ] 没有渐变光晕 / 发光边框 / 彩色阴影
