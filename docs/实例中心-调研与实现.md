# 实例中心：专业面板调研与本次实现

日期：2026-10-10。这里的“专业”按专业服务端管理面板理解；产品继续面向 Minecraft Java。

## 数据模型

逻辑实例是一套运行版本，不是某台电脑上的进程。版本身份包含 Minecraft、服务端／加载器、加载器构建、整合包修订和服务端包标识。每个逻辑实例可以拥有多个存档，每个存档至多拥有一个房间。一个 Minecraft 存档里的主世界、下界和末地不拆成独立存档。

创建实例不选择计算节点。房间记录当前存档的会话入口和开房意图；执行节点由后续调度决定。当前房间显示“待接入执行器”，不能把意图当成正在运行。

| --- | --- | --- |
| 实例目录 | 创建、查看、编辑、复制空配置、删除空实例；按 MC／加载器／整合包搜索 | 中心真实持久化；不创建游戏进程 |

| 模组／插件 | 服务端／双端清单、文件名、版本、哈希和修订记录 | 目录清单真实保存；文件安装与校验未执行 |
| 成员权限 | 实例级或指定存档授权；撤销即时生效；独立托管批准 | 目录和配置操作的后端授权已经有效 |
| 游戏玩家 | Minecraft UUID、白名单／封禁、OP 等级；所有者／平台管理员维护 | 策略保存到中心；尚未下发到实际服务端 |
| 控制台、文件、任务 | 单列运维页面；已有进程仍使用原有工具与原有权限 | 新逻辑实例暂未绑定这些进程；不授予隐含访问权 |
| 快照、恢复、回滚 | 展示执行器接入状态和功能范围 | 未提供虚假的快照创建／恢复按钮 |
| 审计 | 实例、存档、房间、成员、模组、玩家策略修改记录 | 每实例保留最近 200 条，按可见存档过滤 |

## 权限边界

平台管理员可创建逻辑实例，也可授权指定普通用户创建。获准创建的用户成为自己实例的所有者，不升级为平台管理员。

实例所有者和平台管理员管理成员授权与游戏 OP。其他成员可获授查看实例、查看／创建／修改／删除存档、房间操作、运行配置和模组清单维护。指定存档的授权不能修改整个实例。成员不能继续向他人转授。提供计算的批准是独立布尔授权，不授予这些管理能力或 OP。

中心 API 在真实登录会话／API 身份下逐请求检查。返回给成员的存档、权限范围和操作记录被过滤。新授权不自动改变 MCSManager 旧运行实例的分配；这两类资源当前没有执行绑定。未来绑定时必须把相应能力落实到命令、文件和令牌校验，不能只隐藏按钮。

## 数据保护

已有存档时禁止直接改变版本身份；需要复制运行配置，再实施有快照保护的迁移。存档建立后种子不能直接修改。存在开房请求时先关闭才能修改版本／存档／清单。含存档的实例禁止直接删除。删除存档记录会删除该记录的房间和范围授权，不会删除玩家电脑的实际文件。

持久化通过既有 Storage 适配器，使用中心数据目录 NomadCatalog/catalog.json（或配置的 Redis）。写请求串行执行，失败的写入不进入后续读结果。创建房间的唯一性在后端维护，包括并发请求。
