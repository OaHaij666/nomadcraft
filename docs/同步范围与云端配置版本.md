# 同步范围与云端配置版本（2026-10-10）

状态：按用户最新确认的朋友间互信范围，明确后续实施合同。此文档未对应新增运行代码，不宣称配置版本/候选预下载已实现。

## 核心规则

不做反作弊仍需统一开服环境。云端配置是正式配置，计算节点只承担运行；本地修改不自动成为云端正式版本。文件归属由发布清单指定，平台不维护每个 MOD 的关键配置知识库。

客户端与计算节点使用不同同步范围。普通客户端不接收整个服务端 config 或数据库；云端明确指定的客户端公共配置同步，画质/按键等个人配置保留。候选计算节点则准备当前房间的完整服务端环境、受管配置和最新状态。

| 范围 | 同步方式 | 本地主机修改 |
| --- | --- | --- |
| 发布组件 | MC/加载器/必需 MOD/脚本按固定发布清单安装和检查 | 正式变更通过云端发布 |
| 云端管理的配置 | 云端发布的 config 指定文件、配置模板及管理设置按配置修订下载 | 不自动覆盖中心；下次开服恢复中心指定版本 |
| 房间运行数据 | world/、模组数据库、运行生成的未受管文件随房间状态提交恢复 | 属于正常运行，保存后随交接流转 |
| 玩家个人内容 | 光影/材质/画质/按键/个人数据本地保留 | 允许修改，不触发整实例重装 |

云端不是发布时永久冻结所有 config。管理员可在中心更新文件、删除受管文件并形成新修订；新的开服/交接使用该修订。配置本身允许迭代，但每次运行使用一份确定的版本。

## 低维护的文件归属

发布者指定配置目录/文件，系统记录该修订实际提供的受管文件清单，不在启动时把该目录所有文件纳入严格比较。上传 config 文件时显式成为受管文件；数据库等混合数据可用通用路径规则标记为房间运行数据。无需识别每个 MOD 或凭后缀判断数据库。

某路径不能同时作为云端受管配置和房间运行数据；重叠在发布时解决。模组新生成的配置/文件默认保留到房间状态；管理员需要统一其中某文件时，将其明确发布为受管配置。模组自动重写已有受管配置不触发运行中反复修复，也不自动将改写上传为正式配置。

受管文件只在部署/启动前应用，运行中不持续哈希/覆盖。节点本地修改可以显示为待确认或导出到中心进行明确更新，但不采用最后上传者自动覆盖规则。主动更新 cloud config 与正常存档提交走不同路径。

云端删除文件要有受管删除记录，只删除曾由该配置层管理的路径；不清空 config 目录、不删除未受管数据库或个人文件。

## 候选节点同步时机

1. 配置修订发布后，在线候选节点根据资源/流量策略预下载不可变配置包，离线节点重连后检查。预下载更新缓存，不修改正在运行的目录。
2. 节点领取任务时中心固定该次任务的发布版、配置修订和存档检查点；启动前校验并补齐缓存。预下载不是开服的正确性保证。
3. 使用新的任务工作目录，先恢复房间状态，再应用该次任务的受管配置；中心配置不能被旧存档中的同名文件盖回去。任何阶段失败都不进入 ready。
4. 开服期间中心修改 config，形成待生效修订；正常交接/下次开服生效。确需立即生效时通过正常停服再启动，不假设任意 MOD 支持热更新。
5. 完整房间提交排除云端受管配置作为正式配置的覆盖来源；记录使用的配置修订以便排查和恢复。即使某旧快照含有受管路径，恢复后仍由任务指定的配置覆盖。

候选节点面板应显示已缓存/目标配置版本、下载中/准备好/离线；活动节点显示本次使用版本和待生效版本。缓存配置按房间/实例和修订隔离，不让一间房的 config 覆盖另一间。

## 例子

中心已发布 config/example.toml 的 revision 7。A 用 revision 7 开服，MOD 产生 config/example/cache.sqlite，该数据库并未进入受管清单。数据库是房间状态，正常保存迁移。

管理员在云端将 example.toml 更新为 revision 8。B 可以预下载 revision 8；A 的当前运行目录不被在线覆盖。A 正常停服并提交状态后，B 领取任务时确认 revision 8，恢复数据库再应用 example.toml revision 8。A 本地的旧配置或临时改动不会自动覆盖 revision 8。
